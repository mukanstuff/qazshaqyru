### Референсы (изучи их, но НЕ копируй)

В песочнице ссылки могут не открываться из-за TLS-ограничений — в этом случае работай

  *минимальную планку возможностей*, а не как образец дизайна/копирайта):
  - Два режима работы с приглашением: быстрый пошаговый опросник и продвинутый визуальный
    холст с абсолютным позиционированием, где можно двигать/удалять/создавать любой элемент,
    настраивать анимации, цвета, фон, размеры, слои.
  - Между быстрым и продвинутым режимом можно переключаться в любой момент, состояние не теряется.
  - Визуальный редактор рассадки: холст-схема зала, таскаемые столы (круглые/прямоугольные),
    перетаскивание гостей по столам, план-схема зала.
  - WYSIWYG: что видишь в редакторе — то видит гость.
  - Чего у них **НЕТ** (это наш гандикап, его надо использовать):
    - Нет глубокой интеграции с Каспи (оплата/подарки); у toi.com.kz Каспи вообще скриншотом.
    - Нет реакций и ленты пожеланий с вложенными комментариями.
    - Нет magic-link для ресторанов (чтобы тойхана сама видела рассадку без логина/пароля).
    - Нет HMAC-гостевых ссылок без обязательной регистрации гостя.
    - Нет встроенной статистики (кто открыл приглашение, когда, с какого устройства, RSVPs).
    - Нет массовой рассылки приглашений гостям через WhatsApp/СМС одним кликом из сервиса.
    - Нет встроенного экспорта списка гостей в Excel/PDF с ответами и выбором меню.
    - Шрифты у них KZ_RomulC/KZOptima/KZPFMonumentaPro — проприетарные, мы их НЕ воруем.
    - Ассеты декора у них — их собственность, мы НЕ копируем орнаменты 1-в-1.
    - Их словарь интерфейса (копирайт на кнопках, названия шагов визарда) — их собственность,
      мы используем свои, естественные для казахстанского пользователя формулировки на kz/ru.

- **toi.com.kz** — HTML-template pipeline, iframe-редактор с data-edit-id атрибутами.
  У них 117 статических шаблонов и редактор внутри iframe. Мы НЕ делаем iframe-редактор,
  мы делаем нативный реактовый canvas как технически более современное решение.

### 2.1. Ядро: документ-приглашение (Canvas Document)

Определи строгий TS-интерфейс `InvitationCanvasDocument` и отдельные типы для каждого элемента:

```ts
// src/lib/canvas/types.ts
export interface InvitationCanvasDocument {
  version: 1;
  width: number; // дизайн-ширина (390 = mobile-first, 1200 = desktop preview)
  height?: number; // auto для scroll-страницы, фиксированная — для одностраничных
  background: CanvasBackground;
  elements: CanvasElement[];
  mobile?: InvitationCanvasDocument; // отдельная раскладка для мобильного
  // (автогенерится из desktop, но пользователь может править)
  // meta-поля для шаблонов:
  editorMetadata?: {
    baseTemplateId?: string; // от какого шаблона порождён
    lastModifiedAt: string;
  };
}

export type CanvasElement =
  | TextElement
  | HeadingElement
  | ImageElement
  | ButtonElement
  | ShapeElement
  | DividerElement
  | CoupleNamesElement
  | CountdownElement
  | RsvpFormElement
  | WishesElement
  | ProgramElement
  | MapElement
  | MusicPlayerElement
  | GiftBlockElement
  | QrCodeElement
  | LottieElement
  | VideoBgElement
  | OrnamentElement;

export interface BaseElement {
  id: string; // nanoid
  type: CanvasElement['type'];
  x: number; // в процентах от ширины (0-100)
  y: number; // в пикселях от верха
  w: number; // в процентах ширины
  h: number | 'auto'; // в пикселях или auto
  rotation: number;
  zIndex: number;
  locked: boolean;
  hidden: boolean;
  // === Поля, важные для создания ШАБЛОНОВ из документа (п.2.8) ===
  editableByEndUser?: boolean; // true = пользователь шаблона может править контент
  editableProperties?: EditableProperty[]; // какие именно свойства можно править
  placeholderKey?: string; // например 'groomName', 'eventDate', 'venueAddress'
  // используется wizard'ом для автозаполнения
  templateBindTo?: string; // привязка к данным приглашения (для functional-элементов)
  // === Анимации и адаптив ===
  animation?: AnimationConfig;
  mobile?: Partial<BaseElement>; // оверрайд для мобильной версии
  responsive?: {
    preserveAspect?: boolean;
    hideOnMobile?: boolean;
    hideOnDesktop?: boolean;
  };
}

export type EditableProperty =
  | 'text' | 'imageSrc' | 'color' | 'fontFamily' | 'fontSize'
  | 'bgColor' | 'borderColor' | 'link';

export interface AnimationConfig {
  type: 'none' | 'fade' | 'fadeUp' | 'fadeDown' | 'zoomIn' | 'slideLeft' | 'slideRight' | 'flip';
  duration: number;
  delay: number;
  easing: 'ease' | 'ease-in' | 'ease-out' | 'ease-in-out';
  once: boolean; // проиграть 1 раз при появлении в вьюпорте
}
```

- Все координаты в процентах по ширине для адаптива, вертикаль в пикселях
  (страницы скроллятся вертикально, там абсолютные координаты ок).
- Элементы строго типизированы, не `any`, не `Record<string, any>`.
- Для каждого типа элемента сделай свой интерфейс с его специфичными пропсами
  (например у TextElement — `text`, `fontFamily`, `fontSize`, `fontWeight`, `color`,
  `textAlign`, `lineHeight`, `letterSpacing`, `textShadow`, `italic`, `uppercase`;
  у ImageElement — `src`, `alt`, `objectFit`, `borderRadius`, `borderWidth`, `borderColor`,
  `shadow`, `overlayColor`, `linkHref?`; у ButtonElement — `label`, `href`, `action`,
  `bgColor`, `textColor`, `borderRadius`, `shadow`, `size`; у ShapeElement —
  `shape: 'rect'|'circle'|'line'|'star'|'arrow'`, `fill`, `stroke`, `strokeWidth` и т.д.).
- Сохранение документа в БД: в таблице `Invitation` добавь поля `canvas: Json?` и
  `mobileCanvas: Json?` миграцией; старые поля templateData и т.п. не удаляй.
- Сделай валидацию через zod: `canvasDocumentSchema`, отклоняй любые невалидные
  документы на входе в API (глубокая валидация, безопасность: нет вставки скриптов,
  нет ссылок на javascript: и т.п.).

### 2.2. Продвинутый редактор (Canvas Editor / «Конструктор»)

Это визуальный холст с абсолютным позиционированием. **Название в интерфейсе —
"Конструктор" (ru) / "Конструктор" (kz) или "Егжей-тегжейлі өңдегіш" — но не "Advanced Editor",
не "Pro Mode", не как у shaqyru24**. Своё название, своя микро-копия.

- Весь предпросмотр приглашения — абсолютный холст с масштабом, центрированный,
  с переключателем мобильный/десктопный вид.
- **Клик на элемент** = выделение (своя рамка, не копируй точь-в-точь синюю рамку shaqyru24;
  сделай рамку в брендовом цвете — бордовый `#6b1d3a` с тонким золотым акцентом `#c9a961`,
  хендлеры по углам в виде кружков или квадратов, маркер вращения сверху).
- **Перетаскивание мышом/пальцем** меняет x/y в реальном времени, плавно, без лагов,
  с throttling mousemove через requestAnimationFrame.
- **Ресайз за углы** меняет w/h, с сохранением пропорций по Shift.
- **Вращение** за круглый маркер над выделенным элементом.
- **Правая панель свойств (Инспектор)**: контекстно меняет контролы в зависимости от
  выбранного типа элемента. Не используй подписи "Font family / Font size" — пиши
  по-русски/казахски ("Шрифт", "Размер", "Насыщенность", "Цвет", "Выравнивание",
  "Межстрочный", "Буквенный интервал", "Тень"). Контролы сгруппированы по логическим
  блокам (Текст → Вид → Позиция → Анимация).
  - Текст: контент (textarea либо contentEditable с осторожностью), гарнитура, размер,
    насыщенность, курсив, капс, цвет, выравнивание, межстрочное, буквенный интервал, тень.
  - Изображение: скругление, обводка (цвет/ширина), тень, оверлей-цвет, фит (cover/contain),
    alt-текст, клик-ссылка, кнопка "заменить фото" (открывает наш загрузчик).
  - Кнопка: текст, цвет фона, цвет текста, скругление, тень, действие (RSVP/карта/телефон/ссылка).
  - Фигура: форма, заливка, обводка, прозрачность.
  - Общее для всех: позиция (x/y/w/h числами), угол поворота, z-index (выше/ниже/на передний/на задний),
    блокировка, скрытие, дублировать, удалить.
- **Левая панель — Библиотека элементов**: разделы со своими иконками и названиями
  (не копируй структуру shaqyru24 дословно; логические группы):
  - "Текст" (заголовок, подзаголовок, основной текст, церемониальный-script)
  - "Фото" (загрузить фото, вставить из библиотеки, рамка для фото)
  - "Фигуры" (прямоугольник, круг, линия, звезда)
  - "Декор" (разделители, орнаменты, виньетки — CC0 из public/assets/decorations/)
  - "Кнопки и блоки" (кнопка, карточка программы, блок пожеланий, блок подарков, QR-код)
  - "Интерактив" (счётчик, форма RSVP, лента пожеланий, карта, плеер музыки, блок подарков Каспи)
  - "Медиа" (видео-фон, Lottie-анимация)
  Перетаскивание элемента с палитры на холст = создание в точке дропа с разумными дефолтами.
- **Верхний тулбар**: undo/redo, зум (100/75/50% / по ширине / по экрану),
  переключение мобиль/десктоп, сетка вкл/выкл, направляющие выравнивания
  (когда два элемента выравниваются по краю/центру — линия-подсказка с прилипанием — snap),
  "Назад к быстрому редактированию", "Посмотреть как гость" (открывает `/i/[slug]` в новой вкладке),
  "Сохранить как шаблон" (только для admin/agency — см. п.2.8).
- **Горячие клавиши**: Ctrl/⌘+Z отмена, Ctrl/⌘+Shift+Z возврат, Delete/Backspace удалить,
  Ctrl/⌘+D дублировать, стрелки подвинуть на 1px, Shift+стрелки на 10px,
  Ctrl/⌘+C / Ctrl/⌘+V копировать/вставить, Esc — снять выделение.
- **Автосохранение** с дебаунсом 1 сек, с индикатором "Сохранено… / Сохраняется… / Не сохранено".
  Не триггери автосохранение на каждый mousemove — делай snapshot и отправляй на сервер
  когда пользователь отпустил элемент (pointerup), либо после окончания ввода в инспектор
  (blur или Enter).
- **Многослойность через z-order**: клик правой кнопкой / меню-троеточие на элементе —
  "На передний план" / "На задний план" / "Вперёд" / "Назад".
- **Выделение нескольких элементов** с Shift-клик, групповое перемещение, панель
  выравнивания (влево/право/по центру/распределить равномерно) — не обязателен в первом
  проходе, но желательно к концу Stage 8.

### 2.3. Быстрый режим (Quick Wizard / «Быстрое создание»)

Оставь wizard как точку входа по-умолчанию для НОВЫХ пользователей и для тарифа Free.
Назови его естественно, не "Quick Edit wizard". Например: "Быстрое создание" (ru),
"Жылдам құру" (kz).

- Шаги (один экран — один вопрос, не перегружай):
  1. **Повод** (свадьба/ұзату/сүндет той/тұсаукесер/день рождения/юбилей/корпоратив/другое) —
     от этого зависит дефолтный стартовый шаблон и копирайт (жених/невеста vs ана/бала и т.п.).
  2. **Имена** (в зависимости от повода — имена молодожён / имя юбиляра / родителей и т.д.).
  3. **Дата и время** (календарь + выбор времени).
  4. **Место** (название ресторана/зала + адрес с автокомплитом через 2GIS/Dadata).
  5. **Фото обложки** (загрузка или пропустить).
  6. **Цветовая схема** (палитра из 5-8 готовых: бордо-золото, нежно-розовый, классика-ч/б,
     восточный с орнаментом, пастельный и т.п. — пресеты хранятся как CSS-переменные).
  7. Готово: показывается превью и две кнопки: "Опубликовать бесплатно"
     и "Настроить детали в конструкторе".
- Каждый шаг подставляет значение в соответствующий элемент стартового шаблона через
  `placeholderKey` механизм (п.2.1).
- На тарифе Free быстрый режим доступен полностью, продвинутый конструктор — нет

### 2.7. Фишка-улучшения которых нет у конкурентов (внедри их на гостевой и в редакторе)

3. **Массовая рассылка из сервиса**: в панели гостей после создания приглашения — кнопка

8. **Реакции на пожелания** (уже есть в бэкенде) — стилизовать эмодзи красиво, с тултипом

9. **Кнопка "Добавить в календарь"** (.ics файл генерится на бэке с именем, местом, временем).
10. **Церемониальный шрифт для имен** — использовать Marck Script либо Cormorant italic

### Этап 5. Специализированные элементы

Подключи функциональные элементы, которые не просто декор, а работают с бэкендом:
- **CountdownElement**: обратный отсчёт до eventDate, настраиваемый цвет и размер,
  учёт часового пояса места проведения.
- **CoupleNamesElement**: пара текстов с церемониальным шрифтом и связующим элементом
  ("&" или сердце/орнамент), редактируется через placeholderKey.
- **RsvpFormElement**: форма ответа гостя — подключает существующую логику RSVP из
  бэкенда, стилизуется под дизайн документа (цвета/кнопки/шрифты берутся из темы).
- **WishesElement**: лента пожеланий с реакциями (подключает существующий бэкенд).
- **ProgramElement**: список событий дня с временем, точки редактируются в инспекторе
  как массив `{time, title, description?}`.
