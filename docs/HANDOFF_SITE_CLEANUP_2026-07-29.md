## 0. Главное правило (прочитай дважды)

Прошлые агенты добавляли на сайт «полезную инфу» — тарифы, сравнения с бумажными
приглашениями, «Дизайнерден тапсырыс 150 000 ₸», waitlist-кнопки в WhatsApp,
«Сделаем за вас» — **ничего из этого владелец не просил**. Итог: сайт выглядит сырым
и бредовым, у владельца нет ощущения готового продукта.

Поэтому:

1. **НЕ добавляй новый маркетинговый текст, тарифы, цены, блоки, страницы, кнопки
   по своей инициативе.** Твоя работа — УДАЛЯТЬ шум и СВЯЗЫВАТЬ существующее,
   а не генерировать новое.
2. Если для решения нужен текст, которого нет в этом брифе — задай вопрос владельцу
   в чате. Не «примерно как-то так напишу», а спроси.
3. Эталон дизайна — **лендинг `/kk`** (`src/components/landing/LandingPage.tsx`,
   `SiteMarketingHeader`, `SiteCompactFooter`, токены `us-*` в `globals.css`).
   Все публичные страницы должны ощущаться его продолжением.
4. Перед началом и после каждого логического блока работ:
   `pnpm exec tsc --noEmit` (0 ошибок), `pnpm exec vitest run` (все зелёные),
   `pnpm exec next build` (не падает). На момент передачи все три зелёные — не сломай.
5. Это НЕ mvp-на-отъебись. Это продакшн-сервис. Код и UX — соответствующие.

## 1. Pricing: полностью переделать `/pricing`

### Что сейчас (и что удалить)

`src/app/pricing/page.tsx` → `src/components/landing/PricingPageContent.tsx` рендерит:

- freemium-таймлайн из 3 шагов;
- карточки «Стандарт 3 990 ₸» и «Премиум 4 990 ₸» (`FAMILY_PLANS`) — **удалить**;
- секцию «Ұйымдастырушыларға 9 990 ₸/мес» — заменить (см. ниже);
- `PricingValueCompare.tsx` — сравнение «Қағаз ашықтар 15 000 ₸ / QazShaqyru /
  Дизайнерден тапсырыс 150 000 ₸» — **удалить компонент целиком**, владелец это
  прямо назвал бредом;
- `PricingFeatureFaq.tsx` — аккордеон «Тарифтерге не кіреді» с матрицей
  free/standard/premium/agency — **удалить компонент целиком**.

### Что должно быть (решение владельца)

Ровно **две карточки**:

**Карточка 1 — для обычных пользователей.**
- Заголовок в духе «Одно приглашение» (kz: «Бір шақыру») — финальную формулировку
  согласуй с владельцем, не сочиняй сложных текстов.
- Цена: **«от {MIN} ₸» — динамически из БД**: минимальный `Template.priceKzt` среди
  активных каталожных шаблонов (`isActive: true`, slug из `CATALOG_TEMPLATE_SLUGS`).
  Сейчас это 3 990 ₸ (wedding-luxury), но хардкодить нельзя — каждый шаблон будет
  стоить по-своему, карточка показывает минимум. Страница `/pricing` уже серверная —
  посчитай на сервере и передай в клиентский компонент пропсом.
- Смысл: разовая оплата за одно приглашение на одно мероприятие. Без подписок.
- CTA → `/templates`.

**Карточка 2 — «Для агентств» (kz: «Агенттіктерге»).**
- Цена: **20 000 ₸/мес** (подписка).
- Что входит: постоянный доступ к обучающему курсу (как создавать приглашения,
  как продавать, как вести Instagram) + создание приглашений для клиентов без
  ограничений. Идея владельца: фрилансеры/агентства перепродают наши шаблоны,
  платформа — надёжный «движок» для них.
- CTA: пока можно вести на `/agency` (страницу тоже почистить, см. §5) или
  «Написать в WhatsApp» — уточни у владельца, готова ли онлайн-оплата агентского
  тарифа или пока заявки вручную.

### Синхронизировать кодовую базу тарифов

`src/lib/entitlements/plan-catalog.ts` — сейчас 4 SKU (free/standard/premium/agency),
на них завязаны entitlements, checkout, dashboard, куча тестов.

- `agency.priceKzt`: 9 990 → **20 000**.
- «Премиум» как отдельный публичный тариф больше не существует. Минимально
  безопасный путь: перестать показывать premium в UI (pricing, dashboard, editor
  upsell), не выпиливая SKU из движка entitlements за один заход — иначе разнесёшь
  оплату и тесты. Спланируй это как отдельный шаг и прогони все тесты.
- Цена публикации = `Template.priceKzt` конкретного шаблона
  (`resolvePublicationPriceKzt` в `src/lib/invitations/invitation-pricing.ts` уже
  умеет template-override с клампом 2 990–4 990 — это правильная основа).
- Обнови i18n-ключи `landing.v2.pricing.*` в
  `src/i18n/messages/landing-v2.kz.ts` / `landing-v2.ru.ts`: удали ключи
  standard/premium/matrix*/pricingCompare.(print|designer)* вместе с компонентами,
  чтобы не оставлять мёртвые переводы.
- `PricingTeaser.tsx` на лендинге тоже показывает «Стандарт от 3 990» и таймлайн —
  приведи к той же модели «от {MIN из БД} ₸ за приглашение», без выдуманных тарифов.

## 2. Редактор: новый canvas-редактор должен стать основным

### Текущая реальность (проверено по коду)

- Кнопка «Жасау» в хедере (`SiteMarketingHeader.tsx`, 2 места) →
  `/invitations/edit` — это **СТАРЫЙ** Live Editor (`LiveEditorPage`).
- Все карточки шаблонов (`TemplateCatalogCard` → `quickWizardHref()` в
  `src/lib/shared/quick-wizard-url.ts`) → `/invitations/edit?template=...` — тоже старый.
- Новый canvas-редактор живёт на `/invitations/[id]/canvas`
  (`CanvasEditorClient` → `components/canvas/CanvasEditor`), но попасть в него
  можно ТОЛЬКО из `/create` (QuickWizard → `handleOpenConstructor`), а на `/create`
  **нет ни одной ссылки с сайта**, и вдобавок конструктор закрыт пейволом
  `planSku === 'free' → UpgradeModal` (QuickWizard.tsx:257). Поэтому владелец
  «никак не может попасть» в новый редактор.
- Админский конструктор шаблонов `/admin/templates/builder` — работает, доступен
  из `/admin/templates` («+ новый»), не трогать логику, только дизайн-обёртку.

### Целевой флоу (решение владельца)

1. Пользователь выбирает шаблон (лендинг / `/templates`).
2. Открывается **быстрый визард** (короткие вопросы: имена, дата, место — база
   `QuickWizard` уже есть на `/create`).
3. После визарда — **canvas-редактор с результатом**, но в «простом виде»:
   - чистый предпросмотр приглашения без панелей, палитр и инспекторов;
   - сверху/по краям только необходимое: «Сохранить», «Опубликовать», назад;
   - **внизу по центру кнопка «Редактировать»** — по нажатию раскрывается весь
     функционал редактора (тулбар, палитра элементов, инспектор, слои).
   Владелец сказал: если видишь, как сделать этот паттерн лучше — делай смело,
   но суть «сначала тихий просмотр, полный редактор по явному действию» сохрани.
4. **Пейвол на вход в конструктор убрать.** Модель: создавать и редактировать
   бесплатно, платить при публикации (существующий checkout-флоу). Убери
   `showUpgradeModal`-ветку из `handleOpenConstructor`.

### Что перевести на новый флоу

- «Жасау» в хедере (обе точки в `SiteMarketingHeader`) → выбор шаблона/визард,
  а не `/invitations/edit`.
- `quickWizardHref` / `liveEditorHref` в `src/lib/shared/quick-wizard-url.ts` —
  перенаправить на новый флоу (визард → canvas). Это автоматически починит
  карточки шаблонов, `/invitations/new`, blog/faq/seo-страницы (они все зовут
  эти хелперы или `/invitations/edit`).
- Кнопка «Редактировать» приглашения в `dashboard` / `app/invitations/[id]/page.tsx`
  (`editHref` сейчас → `/invitations/edit?...`) → `/invitations/[id]/canvas`.
- Старый Live Editor (`/invitations/edit`, `components/live-editor/*`): после
  переключения всех входов поставь server-side redirect со старого URL на новый
  флоу (шаблон из query сохраняй). Код Live Editor можно пока не удалять, но он
  не должен быть достижим ни одной кнопкой. Отметь в PR, что он кандидат на удаление.
- Проверь `middleware.ts`: `/invitations/edit` сейчас в исключениях защищённых
  путей — приведи исключения в соответствие новому флоу (визард до логина ок,
  сохранение/canvas — за логином, как сейчас в QuickWizard).
