# Agent Workflow для новых шаблонов

Цель: запускать разработку шаблонов как конвейер из 3 ролей (`архитектор` → `верстальщик` → `UX-критик`) с жёсткими проверками и защитой от зависания.

## 1) Роли и зоны ответственности

## Архитектор

- Проектирует структуру `TemplateManifest` (sections, fields, assets).
- Проверяет совместимость с текущим `SectionRenderer` и quick-edit формой.
- Выдаёт implementation-brief: какие файлы создать/изменить и в каком порядке.

Вход:

- `docs/FIGMA_TEMPLATE_WORKFLOW.md`
- Figma экспорт и список `fld/*` + `asset/*`
- текущие манифесты в `apps/web/src/lib/templates/manifests/`

Выход:

- Чёткий diff-план на файлы (без воды)
- риск-лист (что может сломать RSVP/payments/public page)

## Верстальщик

- Реализует манифест/ассеты/section props по brief.
- Не меняет доменную логику API и оплат.
- Держит mobile-first паритет с Figma (`430`, `390`, `360`).

Вход:

- архитектурный brief
- ассеты в `public/assets/templates/<slug>/`

Выход:

- рабочий код
- список ручных smoke-проверок

## UX-критик

- Проводит жёсткий UX/visual аудит после реализации.
- Ищет регрессии в readability, hierarchy, CTA, mobile ergonomics.
- Возвращает только проблемы и actionable правки.

Вход:

- реализованный шаблон
- конкурентный референс (`docs/COMPETITOR_ANALYSIS.md`)

Выход:

- приоритетный buglist (`critical/high/medium`)
- минимальный patch-план

## 2) Стандартный пайплайн (один шаблон)

1. Архитектор — 30-45 мин.
2. Верстальщик — 90-150 мин.
3. UX-критик — 30-45 мин.
4. Финальные правки — 30-60 мин.

Целевой SLA на шаблон: `3-5 часов`.

## 3) Анти-стагнация (обязательно)

Если этап превышает лимит времени:

- Архитектор > 45 мин: зафиксировать спорные решения, выбрать один путь, передать в реализацию.
- Верстальщик > 150 мин: остановить расширение scope, завершить только core sections, остальное в follow-up.
- UX-критик > 45 мин: выпускать топ-5 проблем, не пытаться покрыть всё за один проход.

Каждые 30-40 минут должна быть контрольная точка:

- что уже готово;
- что блокирует;
- нужен ли fallback-план.

## 4) Чеклист качества перед merge

1. `TemplateManifest` полный: `assets`, `fields`, `sections`.
2. Нет “мертвых” ключей (`fieldBindings`/`assets` реально используются).
3. Шрифты читаемы на RU/KZ, включая `Ә Ө Ұ Ү Қ Ғ Ң Һ І`.
4. Preview и public `/i/[slug]` визуально согласованы.
5. Нет побочных правок в платежах, RSVP, auth.
6. Линтер чистый по изменённым файлам.

## 5) Минимальный шаблон запуска для агента

```text
Задача: добавить новый шаблон <slug> по Figma.

Шаг 1 (архитектор): собери manifest план (fields/assets/sections) + список файлов.
Шаг 2 (верстальщик): реализуй строго по плану, без изменений доменной логики.
Шаг 3 (UX-критик): дай только critical/high/medium проблемы и точечные правки.

Ограничения:
- mobile-first 430/390/360
- не ломать RSVP/payments/public routes
- если этап превышает лимит, включить анти-стагнацию и зафиксировать fallback.
```
