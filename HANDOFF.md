## 1. Владелец и как с ним работать

Пользователь — владелец продукта, **не разработчик**. Он не может сам проверить код и полностью
полагается на то, что модель смотрит на проект честно.

### Постоянные инструкции (повторялись во многих сессиях, приведены близко к оригиналу)

> «до этого весь проект «one-shot»-ом писали дешевые китайские модели… они делали хуйню буквально
> на каждом шагу, и никакие их решения не являются эталоном… не продолжайте лепить говно, которое
> после себя оставили те агенты… не бойтесь кардинальных и фундаментальных изменений, если они
> требуются… вы должны уметь во всем сомневаться»

> «работает — не значит работает нормально»

> оценка «без лжи и приукрас»

Практические следствия:

1. **Ничто в кодовой базе не эталон.** Ни исходный код, ни решения прошлых агентских сессий,
   ни мои собственные из прошлых сессий. Если что-то выглядит странно — оно, скорее всего, и есть
   странное.
2. **Проверять реальными инструментами**, а не по памяти и не по комментариям: grep, живой HTTP,
   браузер, SQL к базе. Комментарии в этом репозитории часто описывают намерение, а не факт.
3. **Радикальные изменения приветствуются.** Пользователь прямо просит предлагать фундаментальные
   переделки, а не косметику.
4. **Честность важнее вежливости.** Когда я нахожу собственную ошибку и говорю о ней — он считает
   это доказательством, что проверка была настоящей. Когда он ругает работу — надо действительно
   оценить, прав ли он, и сказать прямо.
5. **Мат — его обычный регистр, не злость.** Не смягчать ответ, не морализировать.
6. **Не «мелкие правки».** Последняя явная формулировка: «попробуй поискать именно визуальные и
   ux/ui возможности для улучшения вообще всего. можно предлагать кардинальные изменения. можно и
   функциональные улучшения. именно улучшения, не мелкие правки».
7. **Отвечать по-русски.** Вся переписка на русском.

## 2. Что за продукт

**QazShaqyru** — казахстанский SaaS цифровых приглашений. Домен: `C:\shaqyru`, приложение в
`apps/web` (монорепо pnpm, но по сути один воркспейс `web`).

События: свадьба (үйлену тойы), той, **беташар**, **қыз ұзату**, **сүндет той**, **тұсаукесер**,
мерейтой, день рождения, корпоратив.

Пользовательский путь:

```
лендинг → /templates (каталог) → /editor/<slug> (конструктор канваса)
        → публикация → /invitations/<id> (хаб управления)
        → гости, персональные ссылки, RSVP, напоминания, рассадка
гость: /i/<slug>?guest=<token>
```

Двуязычность **ru / kz** — не опция, а суть продукта. Половина приглашений на казахском.
Локаль UI и локаль **самого приглашения** — разные вещи (`document.locale`), и это источник
целого класса багов (см. 7.2).

Монетизация: разовая оплата за шаблон (`Template.priceKzt`) → `fullAccess` → без вотермарки.
Бесплатная публикация — с вотермаркой.

## 4. Окружение: как поднять и не сломать

### 4.1 База данных — порт 55432, НЕ 5432

На машине пользователя **Hyper-V резервирует TCP 5358–5457**, туда попадает 5432. Docker-бинд
`5432:5432` падает, но контейнер при `docker restart` поднимается **без опубликованного порта** —
и `docker ps` показывает голое `5432/tcp` вместо `0.0.0.0:55432->5432/tcp`. Симптом: все страницы
отдают 500 «Can't reach database server».

```bash
docker ps --format "{{.Names}} {{.Ports}}"
# должно быть: invitation_db 0.0.0.0:55432->5432/tcp
```

Если порт голый — пересоздать из корня репо:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --force-recreate postgres
```

Данные в именованном томе `shaqyru_postgres_data`, пересоздание контейнера безопасно.
Проверить резервации: `netsh interface ipv4 show excludedportrange protocol=tcp`.

**Подключение к БД напрямую** (роли `postgres` в контейнере НЕТ):

```bash
docker exec invitation_db psql -U invitation_user -d invitation_db -c "SELECT ..."
```

`DATABASE_URL="postgresql://invitation_user:CHANGE_ME_postgres_password@localhost:55432/invitation_db"`

**Важно:** Prisma CLI читает корневой `.env`, а Next.js — `apps/web/.env.local`. Оба должны
указывать на 55432. Google OAuth-переменные лежат в `apps/web/.env` (не `.env.local`) — поэтому
grep по ним раньше ничего не находил.

### 4.5 Особенности инструментов на этой машине (сэкономит время)

- **`python` / `python3` — заглушка Windows Store, не работает.** Для скриптовых правок файлов
  использовать **node**.
- **Часть файлов в CRLF, часть в LF.** `CanvasEditor.tsx` — CRLF; `sheet.tsx`,
  `PropertiesPanel.tsx`, `EditorSheet.tsx` — LF. Многострочный поиск-замена без учёта этого молча
  не находит строку. Рабочий хелпер:

```js
import fs from 'fs';
let s = fs.readFileSync(p, 'utf8');
const crlf = s.includes('\r\n');
const eol = (x) => (crlf ? x.replace(/\r?\n/g, '\r\n') : x.replace(/\r\n/g, '\n'));
const rep = (a0, b0) => { const a = eol(a0), b = eol(b0);
  if (!s.includes(a)) throw new Error('NOT FOUND: ' + a0.slice(0, 60)); s = s.replace(a, b); };
```

- **Bash heredoc ломается на больших TSX-файлах.** Новые компоненты создавать инструментом Write.
- **`npx vitest` надо запускать из `apps/web`**, из корня бинарь не находится.
- **Браузерная панель:** `computer left_click` регулярно отваливается по таймауту 30 с, а
  программный `window.scrollTo` / `scrollIntoView` игнорируется. Рабочие обходы: клик через
  `javascript_tool` (`el.click()`), проверка состояния через `read_page` / `get_page_text` /
  замеры в DOM. Скриншоты иногда возвращают белые кадры или «page did not finish rendering» —
  повторить вызов отдельно. **Если картинка не получилась, нельзя говорить «проверил визуально».**
- `pnpm shot <url> <out.png> [width]` — альтернативный визуальный цикл через Playwright.

### 5.1 Модель документа канваса

`InvitationCanvasDocument`:

- `version`, `width` (390 мобильный дизайн / 1200 десктоп), `height?`
- `background: { type: 'solid'|'gradient'|'image'|'video', color?, gradient?, imageSrc? }`
- `elements: CanvasElement[]` — **19 типов**: `text`, `heading`, `image`, `button`, `shape`,
  `divider`, `couple-names`, `countdown`, `calendar`, `rsvp-form`, `wishes`, `program`, `map`,
  `music-player`, `gift-block`, `qr-code`, `lottie`, `video-bg`, `ornament`
- `envelopeEnabled?`, `autoScroll?`, `sectionOrder?`, `locale?: 'ru'|'kz'`, `editorMetadata?`

**Система координат:** `x`, `w` — проценты ширины документа (0–100); `y`, `h` — пиксели от верха
документа. На телефоне канвас рендерится в своей ширине и масштабируется CSS-трансформом
(`stageScale = viewportWidth / doc.width`), чтобы абсолютные px (шрифты, радиусы) не «съезжали».

**`placeholderKey`** связывает элемент с полем мастера: `coupleNames`, `groomName`, `brideName`,
`heroTitle`, `heroSubtitle`, `eventDate`, `eventTime`, `venueName`, `venueAddress`, `hashtag`,
`dressCode`, `couplePhoto`, `coverPhoto`, `greetingText`.

**Ловушка:** `couple-names` — отдельный тип со своими полями `first` / `second` / `connector` /
`font` / `color`, у него **нет** поля `text`. Чтение его как текстового элемента возвращает пустоту.
Аналогично: у `couple-names` поле называется `font`, у text/heading — `fontFamily`. Оба хранят
**ключ семейства**, который надо прогнать через `fontStack()` из
`components/canvas/elements/fontStack.ts`, иначе CSS получит бессмысленную строку.

### 5.2 Гости и персональные ссылки

Токен гостя хранится **HMAC-хешем**, как пароль. Следствие: ссылку можно показать владельцу
**только один раз**, в момент выпуска. Напоминания (`/remind`) **перевыпускают токены** и тем
самым ломают уже разосланные ссылки. Это отражено в UI честным предупреждением.

`openRsvp` — по умолчанию **выключен** для традиционных типов событий (свадьба и т.п.):
отвечать можно только по персональной ссылке.

### 6.4 Крупные функциональные находки и починки

**Главная:** *на свадьбе — флагманском сценарии — гость вообще не мог ответить.* Три поломки
подряд: (1) `openRsvp` по умолчанию выключен для традиционных типов; (2) гостевая страница не
получала этот флаг и рисовала форму, которая отвечала 403; (3) UI выдачи персональных ссылок
не существовал — бэкенд был полностью готов, вызывающих не было ни одного. Всё три исправлено и
проверено сквозняком: добавить гостя → выпустить ссылки → открыть персональную ссылку → ответить
с «+1» → строка в БД.

Прочее:

- **`+1` молча терялся** в открытом RSVP (`/api/rsvp/open`): статус `attending_plus_one`
  понижался до `attending`, `hasPlusOne` не выставлялся. У каждой пары недосчитывалось гостей.

## 7. Классы дефектов этого проекта — читать перед любым аудитом

Это самое ценное знание о репозитории. Проект писался почти одним проходом дешёвыми моделями,
и ошибки у него **системные, повторяющиеся**, а не случайные.

### 7.1 «Написано, но никуда не подключено» — самый частый дефект

Код выглядит законченным, проходит typecheck и тесты, и **не вызывается ниоткуда**. Падает молча.
Подтверждённые случаи (все реально отгружались сломанными):

- `canvas-animations.css` — полноценный файл с keyframes; рендерер вешал классы; **файл не был
  импортирован нигде**, `animation-name` резолвился в `none`. Ни одно приглашение никогда не
  анимировалось.
- Google Fonts на гостевой странице — `ensureGoogleFont` вызывался только из редакторского
  `EditableTextView`. На `/i/[slug]` — ноль запросов шрифтов, вся типографика шаблонов была
  невидима гостю.
- `GEMINI_API_KEY` / `GEMINI_IMAGE_MODEL` в `.env.example` — на них не ссылался никакой код.
- `OrnamentElement.flipX/flipY` — в типе и в zod-схеме, игнорируются вьюхой; зеркальная пара
  орнаментов рисовалась двумя одинаковыми копиями.
- `fontFamilySchema` заморожена на 5 шрифтах, пока пикер предлагал 24 — каждое сохранение с
  остальными 19 молча отдавало 400.
- `resolveTemplateBySlug` не выбирал `canvas`, поэтому `createDraftForTemplate` всегда выдавал
  универсальную заглушку независимо от выбранного шаблона.
- Композер `template-kit` никогда не выставлял `animation` — два независимых слома на одной фиче.
- В каталоге не было настоящих шаблонов: рецепты жили в коде, но не были засеяны
  (`seed:templates`), каталог показывал только QA-фикстуру. Превью-картинок как понятия не
  существовало, пока не был написан `make-previews.ts`.
- Бэкенд персональных ссылок гостей — полностью готов, ноль вызывающих (см. 6.4).
- `TEMPLATE_CONFIGS` в `lib/templates/configs.ts` — **пустой объект `{}`**. Из-за этого первая
  ветка `getTemplatePreviewUrl` мертва, и `ALL_TEMPLATE_SLUGS` всегда пуст. Не сломано (есть
  fallback на `previewImageUrl` из БД), но это мёртвый слой. *Не чинилось.*

**Как применять:** когда фича «есть» — сначала убедись, что до неё доходит управление. Grep по
реальным вызовам, проверка, что стайлшит импортирован, и подтверждение поведения в живом продукте.

### 7.2 Захардкоженная локаль и захардкоженная тема внутри «настраиваемого»

- Рендерер по умолчанию брал `ru` — казахское приглашение показывало «ПН ВТ СР» в календаре и
  русские кнопки RSVP. Исправлено через `document.locale`.
- `RsvpFormElementView` содержал литеральный бордовый `rgba(107,29,58,…)` и `#dcd3cb` — воевал с
  любой палитрой, кроме исходной.
- `EnvelopeGate` показывал русское «Нажмите, чтобы открыть» всем (исправлено этой сессией).
- `CanvasGuestPage` показывал русское «Загрузка…» всем (исправлено этой сессией).
- **Осталось:** `SheetCloseButton` в `components/ui/sheet.tsx` — `aria-label="Закрыть"` жёстко
  по-русски. Компонент раскрывает `{...props}` **после** атрибута, так что вызывающий может
  переопределить, но никто не переопределяет.
- **Осталось:** `components/seo/SeoEventLanding.tsx` — строки `allTemplatesLabel`, `faqLabel`,
  `createLabel`, `relatedHeading`, `faqHeading` собраны тернарниками `locale === 'kz' ? … : …`
  прямо в компоненте, мимо i18n-дерева.

### 7.3 CSS-ловушки, видимые только на конкретной ширине или в конкретной последовательности фокуса

- Ручка вращения: инлайновый `style={{left: calc(...)}}` из **документных** координат перебивал
  центрирование из стайлшита; ручка уезжала от элемента, а поскольку угол меряется от настоящего
  центра, крошечное движение мыши давало огромный поворот.
- `position:fixed` внутри предка с `translate3d(0,0,0)` резолвится относительно предка, а не
  вьюпорта — тулбар улетал на сотни пикселей. Лечение: портал в `document.body`.
- Анимация открытия шторки: центрирование через `left:50%; -translate-x-1/2` (оба на свойстве
  `transform`) конфликтовало с keyframe, которая тоже анимирует `transform` — анимация заменяет
  свойство целиком, центрирование пропадало на время анимации. Лечение: центрировать
  `inset-x-0; margin-inline:auto`.
- z-index дока против канваса: схема разрешает элементам zIndex до 10000, закреплённый хром сидит
  на ~9990; без `isolation:isolate` на корне сцены они конкурируют напрямую.
- Сирота фокуса: свотч цвета — обычный `<button>` (в отличие от соседей, которые `preventDefault`
  на `pointerdown` именно ради этого). Клик даёт ему фокус, затем `setShowColor(false)`
  размонтирует сфокусированную кнопку, браузер роняет фокус на `<body>`. React-состояние
  оставалось верным, DOM-фокус — потерянным. Лечение потребовало двух слоёв: явно возвращать фокус
  при закрытии поповера **и** безусловно сбрасывать `editingTextId` при смене выделения.
- **Специфичность медиазапросов:** в этой сессии я сам напоролся — правило ширины лежало в
  `@media (min-width: 600px)`, мой блок шёл **ниже** по файлу; медиазапрос не добавляет
  специфичности, поэтому моё правило выиграло, и карточка растянулась на всю ширину, пока хедер
  и список сидели в колонке 640px.

**Как применять:** любой `position:fixed` — проверить всех предков на
`transform`/`filter`/`will-change`/`perspective`. Любая keyframe, трогающая `transform`, —
проверить, что ещё пишет `transform` на том же элементе. Любой контрол, крадущий фокус, — иметь
план, куда фокус уйдёт при размонтировании.

### 7.4 Недостижимое условие срабатывания

Код выполняется, но условие никогда не становится истинным. QuickWizard авто-открывался по
проверке «плейсхолдеры пустые», а настоящие шаблоны поставляются с демо-текстом
(«Айдар және Айсұлу») — пустыми они не бывают, мастер не открывался никогда. Вдобавок у самого
старого живого шаблона `elegant-gold-wedding-01` не было ни одной привязки `placeholderKey` на
всех 13 элементах, так что даже после починки триггера ответы мастера некуда было класть, пока
строку в БД не пропатчили руками.

### 7.5 Механически испорченный JSX

Не «недописанный», а **повреждённый** прошлым автоматическим редактированием, которое вырезало
все `className`/`style` из файла, оставив логику. Найдено в `/api/og/route.tsx` (у каждого JSX-узла
пустой слот, где был `style=`; Satori требует явный `display:flex` на многодетном div — роут
отдавал 400 поверх настоящего бага маршрутизации) и независимо в
`components/publish/SendInvitesModal.tsx` + `PublishChecklistModal.tsx` (0 вхождений `className=`
на 309 и 254 строки соответственно, в файлах с полноценным UI модалки).

**Признак:** компонент с явно богатым UI, но числом `className=` около нуля относительно длины.
Стоит прогонять `grep -c "className="` на любом файле, которому собираешься доверять.

### 7.6 Конкурирующие параллельные подсистемы

Старая подсистема остаётся на месте, когда рядом строится новая. Исторический пример
(`lib/canvas/sections.ts` с захардкоженными `BRAND.primary` и русским текстом против
тема-зависимого `ElementPalette.tsx`) — **уже исправлен**: `sections.ts` берёт цвета/шрифты/локаль
из документа через `deriveSectionContext(doc)`, а секции, полностью дублировавшие атомарные
элементы (`program`, `wishes`, `rsvp`, `gift`), удалены из `TEMPLATE_SECTIONS`. Паттерн остаётся
живым риском — искать новые экземпляры.

  периодически возвращаются белыми — это артефакт композитинга, а не продукт. Я дважды в прошлой

  несуществующий `.jpg`, ровно три активных шаблона.
- **Комментировать «почему», а не «что».** В этом репозитории принят стиль развёрнутых
  комментариев над нетривиальными местами, объясняющих, что было сломано и почему сделано так.
  Придерживаться его — он уже спас несколько регрессий.
